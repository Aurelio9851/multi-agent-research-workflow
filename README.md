# Multi-Agent Scientific Research Workflow with LangGraph

A lightweight **multi-agent scientific research pipeline** built with LangGraph, designed to automate the process of planning, finding papers, writing, reviewing, and improving a literature review.

The workflow combines **LLM-based agents, arXiv search, shared state, conditional routing, and iterative refinement** to produce a research report that is reviewed and improved until it reaches a predefined quality threshold.

## Architecture

The workflow is organized as a directed graph:

```text
                         ┌─────────────┐
                         │   Planner   │
                         └──────┬──────┘
                                │
                                ▼
                         ┌─────────────┐
                         │  Researcher │
                         └──────┬──────┘
                                │
                                ▼
                         ┌─────────────┐
                         │   Writer    │
                         └──────┬──────┘
                                │
                                ▼
                         ┌─────────────┐
                         │   Reviewer  │
                         └──────┬──────┘
                                │
                    ┌───────────┴───────────┐
                    │                       │
             score >= 80              score < 80
                    │                       │
                    ▼                       ▼
                   END               ┌─────────────┐
                                     │  Improver   │
                                     └──────┬──────┘
                                            │
                                            ▼
                                     ┌─────────────┐
                                     │   Reviewer  │
                                     └─────────────┘
```

## Workflow

The system implements the following pipeline:

```text
Question
   │
   ▼
Planner
   │
   ▼
Researcher
   │
   ▼
Writer
   │
   ▼
Reviewer
   │
   ├── score >= 80 ──► END
   │
   └── score < 80 ──► Improver
                           │
                           ▼
                       Reviewer
```

The workflow starts from a research question and progressively transforms it into a literature review.

The reviewer acts as a quality gate. If the generated report receives a score of at least **80/100**, the workflow terminates. Otherwise, the report is sent to the improvement agent and reviewed again.

## Agents

### 1. Planner

The planner analyzes the initial research question and identifies the research aspects that should be investigated.

```python
def planner_agent(state):
    question = state["question"]
    ...
```

It produces a `research_plan` containing the generated research aspects.

### 2. Researcher

The researcher searches **arXiv** using the original research question.

```python
search = arxiv.Search(
    query=query,
    max_results=5
)
```

For each paper, the agent extracts:

* title
* abstract/summary
* arXiv URL

The results are stored in the shared `papers` state.

### 3. Writer

The writer receives the retrieved papers and generates the initial scientific literature review.

The prompt explicitly asks the agent to cover:

* main approaches
* comparison
* limitations
* future directions

The generated report is stored in:

```python
state["report"]
```

### 4. Reviewer

The reviewer evaluates the generated literature review using an LLM.

It is asked to provide:

```text
SCORE: number

FEEDBACK:
text
```

The result is stored as:

* `quality_score`
* `review_feedback`

The score is then used by the graph router to determine whether the workflow should terminate or continue.

### 5. Improver

If the report does not reach the required quality threshold, the improvement agent receives:

* the current report
* the reviewer feedback

It then generates an improved version of the report.

The improved report is passed back to the reviewer, creating an iterative feedback loop.

## Shared State

The agents communicate through a common `ResearchState` defined using `TypedDict`:

```python
class ResearchState(TypedDict):

    question: str
    research_plan: List[str]
    papers: List[dict]
    context: List[str]
    report: str
    quality_score: int
    review_feedback: str
```

The state contains the information accumulated throughout the workflow:

| Field             | Description                               |
| ----------------- | ----------------------------------------- |
| `question`        | Original research question                |
| `research_plan`   | Research aspects generated by the planner |
| `papers`          | Papers retrieved from arXiv               |
| `context`         | Extracted information from papers         |
| `report`          | Current literature review                 |
| `quality_score`   | Review score from 0 to 100                |
| `review_feedback` | Feedback generated by the reviewer        |

Using a shared state allows each agent to focus on a specific task while passing its output to the next stage.

---

## Conditional Review Routing

The review stage uses a simple router:

```python
def review_router(state):

    score = state["quality_score"]

    if score >= 80:
        return "approved"
    else:
        return "improve"
```

This creates a quality-controlled feedback loop:

```text
                    Reviewer
                       │
              ┌────────┴────────┐
              │                 │
          score >= 80        score < 80
              │                 │
              ▼                 ▼
             END             Improver
                                │
                                ▼
                             Reviewer
```

The threshold is currently set to **80/100**.

## LangGraph Workflow

The graph is constructed using `StateGraph`:

```python
workflow = StateGraph(ResearchState)
```

The main nodes are registered as:

```python
workflow.add_node("planner", planner_agent)
workflow.add_node("researcher", researcher_agent)
workflow.add_node("writer", writer_agent)
workflow.add_node("reviewer", reviewer_agent)
workflow.add_node("improver", improvement_agent)
```

The sequential part of the workflow is:

```python
workflow.add_edge("planner", "researcher")
workflow.add_edge("researcher", "writer")
workflow.add_edge("writer", "reviewer")
```

The reviewer then controls the execution path:

```python
workflow.add_conditional_edges(
    "reviewer",
    review_router,
    {
        "approved": END,
        "improve": "improver"
    }
)
```

Finally, the improvement loop connects back to the reviewer:

```python
workflow.add_edge(
    "improver",
    "reviewer"
)
```

The graph is compiled with:

```python
graph = workflow.compile()
```

## Key Concepts Demonstrated

This project is primarily an implementation exercise in **agentic workflow orchestration** rather than a fully autonomous research system.

It demonstrates several important concepts:

### Multi-Agent Architecture

Different LLM agents are assigned specialized responsibilities instead of asking a single model to perform the entire task.

### Stateful Execution

A shared `ResearchState` allows information to flow between agents.

### Tool-Based Research

The researcher agent uses the arXiv API to retrieve scientific papers.

### Conditional Routing

The workflow dynamically decides what to do after the review stage based on the generated quality score.

### Iterative Self-Improvement

The `reviewer → improver → reviewer` loop introduces an iterative refinement mechanism.

### Graph-Based Orchestration

LangGraph represents the workflow explicitly as a graph rather than as a collection of manually chained function calls.

## Current Limitations

This implementation is intentionally lightweight and has several areas that could be improved.

### Planner Output

The planner currently returns the complete LLM response as a single list element rather than parsing it into individual research aspects.

### Research Strategy

The researcher currently performs a single arXiv search using the original question and retrieves a maximum of five papers.

The generated research plan is not yet used to perform multiple targeted searches.

### Context Extraction

Although `ResearchState` contains a `context` field, the current researcher does not populate it with extracted information from the papers.

### Review Score Parsing

The reviewer currently uses simple string matching to extract the score:

```python
score = 50

if "90" in text:
    score = 90
elif "80" in text:
    score = 80
```

This is a simplified implementation and can produce incorrect scores when the LLM returns values other than 80 or 90.

### Iteration Control

There is currently no explicit maximum number of improvement iterations.

A production implementation should introduce a maximum iteration count or another termination condition.

## Example Execution

A research request starts from a state such as:

```python
{
    "question": "How are large language models used for cybersecurity?",
    "research_plan": [],
    "papers": [],
    "context": [],
    "report": "",
    "quality_score": 0,
    "review_feedback": ""
}
```

The graph then executes:

```text
Question
   ↓
Planner
   ↓
Researcher
   ↓
Writer
   ↓
Reviewer
   ↓
┌───────────────────┐
│ Quality >= 80 ?   │
└─────────┬─────────┘
          │
      ┌───┴───┐
     YES      NO
      │        │
      ▼        ▼
     END    Improver
                │
                ▼
             Reviewer
```

The final output is the literature review stored in:

```python
state["report"]
```

while the latest evaluation and feedback are available through:

```python
state["quality_score"]
state["review_feedback"]
```
